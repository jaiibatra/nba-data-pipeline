# NBA Data Pipeline

An end-to-end data pipeline that pulls NBA player and team data from the NBA Stats API, stores it in a SQLite database, and serves it through an interactive Streamlit dashboard.

**Tech:** Python, pandas, SQLite/SQL, `nba_api`, Streamlit, Git

## What It Does

- **Extract:** fetches all 30 team rosters and league-wide player season stats via the [`nba_api`](https://github.com/swar/nba_api) package
- **Transform:** cleans API responses with pandas
- **Load:** stores data in two joinable SQLite tables, `players` (roster info) and `player_stats` (season totals, keyed by `player_id` + `season`)
- **Serve:** query with SQL or explore through a Streamlit dashboard with a player picker

## Setup

```bash
git clone https://github.com/jaiibatra/nba-data-pipeline.git
cd nba-data-pipeline
pip install nba_api pandas streamlit
```

## Usage

```bash
python explore_stats.py    # build nba.db (about 31 API calls, takes a minute or two)
streamlit run app.py       # launch the dashboard at http://localhost:8501
python query_db.py         # run example SQL queries
```

If a few teams print `Read timed out`, the NBA's servers are just slow. Re-run the script and it will rebuild the tables.

`nba.db` is generated by the pipeline and is not committed.

## Design Notes

- **Composite primary key** `(player_id, season)` lets a player have one stats row per season.
- **League-wide stats fetch** instead of per-team: players traded mid-season appeared on two teams, which broke the primary key and dropped data. One league-wide call returns a single combined row per player.
- **`try`/`except` around requests** so API timeouts don't stop a run.

## Limitations

Currently loads only the 2023-24 season. Stats are season totals, not per-game averages.
